# PMO EPC Platform

Version : 0.1 (Architecture)

---

# Objectif

PMO EPC Platform est une plateforme de gestion de projets EPC (Engineering, Procurement & Construction).

Elle a pour objectif de réunir dans une seule application les fonctionnalités de :

- PMO
- GED / EDMS
- Planning
- Cost Control
- Risk Management
- Reporting
- EVM
- Handover

Le projet est développé sous Django.

Le but n'est pas de reproduire MS Project ou Primavera, mais de construire une plateforme PMO complète, intégrant les concepts de ces outils.

---

# Philosophie

Le projet est organisé autour des objets métier.

La hiérarchie principale est :

Conteneur documentaire
    Projet
        Commande
            Tâches

Les autres modules viennent s'appuyer sur cette hiérarchie.

Exemple :

Projet
    ├── Commandes
    ├── Documents
    ├── Planning
    ├── Coûts
    ├── Risques
    ├── Reporting
    └── Handover

# Différence entre les deux modules Planning

Le projet comporte volontairement deux modules différents.

## 1. Suivi des tâches

Le premier module est basé exclusivement sur les tâches existantes.

Il ne possède pas son propre modèle.

Il calcule automatiquement :

- planning projet
- planning commande
- Gantt
- calendrier
- retards
- jalons
- charge

Il constitue une vue analytique des données existantes.

Il dépend directement du modèle Tache.

---

## 2. Planning Project

Le second module est un véritable moteur de planification.

Il possède ses propres modèles.

Il permettra de gérer :

- Baselines
- Versions
- Dépendances
- Ressources
- Calendriers
- Contraintes
- Chemin critique
- Nivellement
- Planning maître

Son fonctionnement sera proche de Microsoft Project ou Primavera.

---

# GED

Le module GED constitue le cœur documentaire.

Tous les documents sont rattachés :

Projet
    Commande
        Document

Les tâches pourront également référencer des documents existants.

Le stockage documentaire est indépendant du module Planning.

# Philosophie des Services

Les vues Django restent volontairement très légères.

Chaque vue appelle un service spécialisé.

Exemple :

views.py

↓

services/dashboard.py

↓

services/gantt.py

↓

services/projet.py

Les traitements métier ne doivent jamais être placés dans les vues.

---

# Philosophie des composants

Une page assemble uniquement des composants.

Exemple :

dashboard.html

↓

planning_header

planning_toolbar

planning_filters

planning_statistics

planning_summary

Les composants ne doivent contenir que de la présentation.

Toute logique métier reste dans les services.
