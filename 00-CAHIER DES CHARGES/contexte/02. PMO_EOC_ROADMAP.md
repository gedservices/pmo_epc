# Objectif

Ce document décrit l'état d'avancement du projet ainsi que l'ordre dans lequel les modules doivent être développés.

Il constitue la référence principale pour poursuivre le développement, quel que soit l'outil (ChatGPT, Claude, DeepSeek, Gemini, développeur humain...).

---

# Philosophie de développement

Le projet est construit de manière incrémentale.

Chaque application doit respecter les mêmes principes :

- architecture homogène
- services spécialisés
- vues légères
- composants réutilisables
- logique métier centralisée

Les nouveaux développements doivent préserver cette cohérence.

# Règles de développement

Chaque nouvelle application doit respecter la structure suivante :

apps/

nom_application/

models.py

views.py

urls.py

forms.py

services/

dashboard.py

...

templates/

nom_application/

dashboard.html

...

Les traitements métier doivent être placés dans les services.

Les vues restent les plus simples possibles.

Les templates ne contiennent pas de logique métier.

Les composants graphiques sont mutualisés dans :

templates/base/components/

---

# Décisions d'architecture

## Deux modules Planning

Le projet distingue volontairement deux modules.

### Suivi des tâches

Vue analytique.

Basé uniquement sur les tâches existantes.

Aucun modèle spécifique.

---

### Planning Project

Véritable moteur de planification.

Dispose de ses propres modèles.

Comparable à Microsoft Project ou Primavera.
